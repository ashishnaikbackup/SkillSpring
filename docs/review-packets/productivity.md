## Course introduction

Build sustainable systems for planning, focus, note-taking, learning and workflow improvement. Tools should support priorities, not create busywork.

## Lessons

### 1. Goals, priorities and weekly planning

**Concept.** A goal describes an outcome; a task is an action. Break large goals into next actions, estimate effort and schedule realistic blocks. Review priorities when circumstances change.

**Example**

```
Instead of 'learn Excel', define 'complete formulas lesson and build a SUMIFS tracker by Friday'. The second has a visible deliverable and deadline.
```

**Explanation / note.** Specific actions make progress observable.

**Task.** Choose one learning goal. Break it into five actions, estimate time and schedule a realistic week with buffer.

**Quiz.** What makes a goal actionable?
- Correct: A clear outcome, next action and time frame
- Wrong: A vague wish with no next step
- Wrong: A list of unrelated tasks

### 2. Focus and attention management

**Concept.** Focused work reduces context switching. Use short planned sessions, remove avoidable distractions and take breaks. Match task difficulty to available energy. Do not treat a timer as a substitute for rest or health needs.

**Example**

```
A 30-minute session can have one defined outcome: solve three SQL questions, check answers and write down one mistake to revisit.
```

**Explanation / note.** A defined outcome limits task switching and vague activity.

**Task.** Plan a 45-minute learning session with one goal, materials ready, distraction plan and a short review.

**Quiz.** Why choose one clear outcome for a focus session?
- Correct: It makes attention and completion easier to evaluate
- Wrong: It guarantees no mistakes
- Wrong: It removes the need for breaks

### 3. Notes and knowledge capture

**Concept.** Good notes preserve useful ideas in your own words and link them to questions, examples and sources. Separate facts, assumptions and personal reflections. Keep notes searchable with consistent titles and tags.

**Example**

```
A concept note can contain definition, worked example, common mistake, one question and source link. This is more useful than copying a full chapter.
```

**Explanation / note.** Notes should help you retrieve and apply ideas.

**Task.** Turn one lesson into a one-page note using definition, example, mistake, question and source.

**Quiz.** What makes a note useful for later recall?
- Correct: Clear structure, own words, examples and retrieval questions
- Wrong: Copying every sentence without processing
- Wrong: A title with no content

### 4. Active recall and spaced practice

**Concept.** Active recall means retrieving information without looking at the answer. Spaced practice revisits material over increasing intervals. Interleave related problem types when useful and correct mistakes with explanations.

**Example**

```
After studying subnetting, close the notes and calculate a new network range. Check the result, explain the error and retry later.
```

**Explanation / note.** Retrieval practice tests whether knowledge can be used without prompts.

**Task.** Create a 7-day review schedule for one topic with short recall questions and one cumulative problem.

**Quiz.** What is the main benefit of active recall?
- Correct: It strengthens retrieval and reveals gaps in understanding
- Wrong: It makes reading unnecessary
- Wrong: It guarantees perfect memory

### 5. Digital organisation and information hygiene

**Concept.** Use clear file names, folders, version history and backups. Separate personal and public files. Use a password manager and MFA where possible. Avoid storing secrets in shared notes or public repositories.

**Example**

```
A project folder can contain /docs, /data, /src and /exports, with README and dated releases. Keep private data outside a public repository.
```

**Explanation / note.** A backup should remain recoverable if the primary copy fails.

**Task.** Organise a fictional project folder, write a naming convention and create a backup/restore checklist.

**Quiz.** Why keep a backup separate from the working copy?
- Correct: To recover if the working copy is lost or corrupted
- Wrong: To make duplicate files confusing
- Wrong: To publish private data

### 6. Workflow improvement and automation

**Concept.** A workflow is a repeatable sequence of steps. Map inputs, decisions, outputs and exceptions before automating. Automate stable repetitive tasks; keep human approval for consequential decisions and check failure paths.

**Example**

```
Before automating reminders, identify the trigger, recipient, message, duplicate prevention, failure notification and owner.
```

**Explanation / note.** Automating a poorly understood process can make errors happen faster.

**Task.** Map one repetitive study or office task. Identify which steps are safe to automate and which need a human check.

**Quiz.** What should happen before automating a process?
- Correct: Understand the process, exceptions, risks and desired outcome
- Wrong: Automate every step immediately
- Wrong: Remove all checks
