## Course introduction

Learn how to find suitable roles, prove your skills, explain projects, answer behavioural and technical questions and prepare professionally.

## Lessons

### 1. Understand roles & job descriptions

**Concept.** A job description lists responsibilities, essential skills and preferred skills. Separate must-have requirements from nice-to-have items. Research the organisation and the actual work rather than applying by title alone.

**Example**

```
Choose a sample job description. Highlight tools, core concepts, responsibilities, experience expectations and repeated keywords. Build a skill-gap table.
```

**Task.** Deliverable: a role analysis with evidence you already have and gaps to close.

**Quiz.** What should you do before tailoring an application?
- Correct: Understand the role's responsibilities and required evidence
- Wrong: Copy the same CV for every role
- Wrong: Claim every listed skill

### 2. CV, resume & application basics

**Concept.** A CV should be truthful, concise and relevant. Use clear sections, reverse chronology where appropriate, measurable outcomes and action verbs. Avoid fabricated metrics, misleading skill levels and unnecessary personal data.

**Example**

```
Write a one-page entry-level CV with education, skills, projects, experience and links. For each project, state the problem, your contribution, tools and outcome.
```

**Task.** Create a role-tailored CV and a short application note.

**Quiz.** What makes a project bullet stronger?
- Correct: Specific contribution, tools used and verifiable outcome
- Wrong: A long list of buzzwords
- Wrong: Unverified claims

**Findings:** _none yet_

### 3. Portfolio & project storytelling

**Concept.** A portfolio demonstrates evidence. Each project should explain context, problem, your role, design or technical decisions, implementation, tests, limitations and next steps. Keep repositories reproducible.

**Example**

```
Select one project. Improve README, setup instructions, screenshots, architecture diagram, test evidence and known limitations. Prepare a 90-second explanation.
```

**Task.** Deliverable: one polished project case study with a live demo or clear screenshots.

**Quiz.** What should a credible project case study include?
- Correct: Problem, your contribution, process, evidence and limitations
- Wrong: Only a logo
- Wrong: Only copied source code

**Findings:** _none yet_

### 4. Behavioural questions & STAR

**Concept.** Behavioural interviews assess how you acted in real situations. STAR means Situation, Task, Action and Result. Be specific about your own contribution and explain what you learned. Do not invent a story.

**Example**

```
Prepare examples for teamwork, conflict, failure, initiative, learning quickly and meeting a deadline. Use STAR and keep the action section specific.
```

**Task.** Create six concise STAR stories based on genuine experiences or clearly labelled academic examples.

**Quiz.** In STAR, what does A represent?
- Correct: Action you personally took
- Wrong: Audience
- Wrong: Assumption

**Findings:** _none yet_

### 5. Technical interviews & problem solving

**Concept.** Technical interviews assess fundamentals and reasoning. Clarify the problem, state assumptions, consider edge cases, explain an approach, test it and discuss complexity or trade-offs where relevant. Think aloud clearly.

**Example**

```
Practise explaining a basic concept, solving one role-relevant problem and testing boundary cases. If stuck, describe what you know and ask a clarifying question.
```

**Task.** Build a 20-question technical revision sheet for your target role.

**Quiz.** What is a good first step when a technical prompt is unclear?
- Correct: Ask clarifying questions and state assumptions
- Wrong: Immediately guess
- Wrong: Stay silent

**Findings:** _none yet_

### 6. Communication, group discussion & presentation

**Concept.** Speak clearly, structure answers and listen actively. In group discussions, contribute evidence, build on others' points and disagree respectfully. Presentations should have a clear opening, logical flow and conclusion.

**Example**

```
Record a 2-minute introduction and a 3-minute project explanation. Review clarity, pace, filler words and whether your contribution is understandable.
```

**Task.** Prepare an introduction, project pitch and one presentation with Q&A.

**Quiz.** What is effective disagreement in a group discussion?
- Correct: Respectfully explain reasoning and evidence while listening
- Wrong: Interrupt repeatedly
- Wrong: Dismiss other views

**Findings:** _none yet_

### 7. HR, salary, ethics & workplace readiness

**Concept.** Prepare honest answers about motivation, strengths, learning areas and availability. Research market ranges carefully. Never share confidential data or misrepresent credentials. Ask about role expectations, mentorship and success measures.

**Example**

```
Practise answers to why this role, strengths, a learning challenge, joining timeline and questions for the interviewer. Draft a professional follow-up message.
```

**Task.** Create a one-page interview preparation brief for a real target role.

**Quiz.** If asked about a skill you do not know, what is best?
- Correct: Be honest, explain adjacent knowledge and how you would learn it
- Wrong: Pretend to be an expert
- Wrong: Invent experience

### 8. Mock interviews, assessment & 30-60-90 plan

**Concept.** Practise under realistic time limits. Review answer quality, technical accuracy, clarity and evidence. After an interview, reflect on gaps and plan focused improvement. A course cannot guarantee selection.

**Example**

```
Run a mock interview with a peer or recording. Score answers against a rubric: accuracy, structure, evidence, clarity and reflection. Create a 30-60-90 day learning plan.
```

**Task.** Capstone: CV, portfolio, target-role analysis, six STAR stories, technical revision sheet, mock interview review and follow-up template.

**Quiz.** What is the purpose of a mock interview review?
- Correct: Find specific gaps and improve the next attempt
- Wrong: Guarantee a job offer
- Wrong: Memorise one script for every question
