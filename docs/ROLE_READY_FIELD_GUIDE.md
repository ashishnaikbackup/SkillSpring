# SkillSpring Role-Ready Field Guide — Zero to Professional

## Why this guide exists

This guide turns the 12 learning schools into practical learning-to-work pathways. It is a **curriculum and evidence standard**, not a job guarantee or an accredited qualification. A learner is ready to apply for an entry-level role when they can complete the role's typical tasks independently, explain their decisions, show original work, communicate clearly and pass a practical assessment.

A course title, badge, watched video or copied project is not hiring evidence. Every learner must create and defend their own work.

## The common route every learner follows

1. **Start at zero:** digital literacy, file management, safe tool setup, vocabulary, units and prerequisites.
2. **Learn first principles:** understand what a tool or concept does, why it exists, its inputs/outputs and common failure modes.
3. **Practise one skill at a time:** follow worked examples, then guided exercises, then unseen independent tasks.
4. **Learn the professional workflow:** versioning, documentation, quality checks, privacy, security, accessibility, ethics and collaboration.
5. **Build evidence:** complete a small, medium and advanced project with acceptance criteria and a written explanation.
6. **Demonstrate competence:** take a timed practical, debug an unfamiliar issue, explain trade-offs and answer role-specific questions.
7. **Prepare to apply:** create a truthful role-specific CV, portfolio, project walkthrough and interview practice record.

### The standard lesson format

Every fully authored lesson must include: prerequisites; learning outcomes; plain-language explanation; defined terminology; annotated worked example; guided task; independent task; expected output or solution explanation; common mistakes; knowledge check with feedback; professional relevance; references and review date where facts or software versions change.

### What counts as hiring evidence

- The learner can reproduce the result from a clean setup without copying a tutorial.
- The work solves a clearly stated problem and meets measurable acceptance criteria.
- The learner can explain architecture, calculations, design choices, limitations and alternatives.
- The work has appropriate tests, validation, safety/privacy/accessibility checks and documentation.
- The learner can demonstrate it live and respond to a change request.
- The portfolio states exactly what the learner did; no fabricated clients, credentials, metrics or team contributions.

## School 1 — Programming & Software Development

**What the field does:** turns requirements into software that reliably processes information and solves user or business problems.

**Beginner foundations:** computer/file literacy; terminal and editor use; input-process-output; algorithms and pseudocode; variables, types, operators, conditions, loops, functions and collections. Explain memory and execution before advanced language features.

**Professional progression:** choose one primary language; learn data structures and algorithmic complexity; OOP and composition; error handling; debugging; unit/integration tests; Git branches and pull requests; SQL and data modelling; HTTP/API design; authentication concepts; secure configuration; logging; deployment; architecture and maintenance. Add a second language only after the learner can build and test a complete program in the first.

**Tools to practise:** one language/runtime (Python, JavaScript, Java, C, C++ or another role-relevant choice), VS Code or equivalent, Git/GitHub, terminal, debugger, test framework, SQL database, API client and deployment platform. Tool choice must be free-first where possible.

**Portfolio sequence:**
- Beginner: CLI calculator, unit converter or expense tracker with input validation and tests.
- Intermediate: database-backed application or API with authentication concepts, error handling and automated tests.
- Advanced: deployed application with documented architecture, CI checks, security considerations, logs, issue history and maintainability plan.

**Entry roles:** junior software developer, QA automation trainee, scripting/automation assistant, application support developer. A learner needs role-specific depth; a broad language list is not a substitute.

**Hiring proof:** solve unseen programming tasks; explain Big-O at a basic level; write and test functions; debug a failing test; use Git; query SQL; explain an API request/response; walk through a project and its limitations.

**Interview preparation:** variables/types, control flow, functions, arrays/maps, strings, OOP, exceptions, testing, SQL joins, HTTP, data structures, complexity, debugging and project decisions. Practise explaining thought process, not memorised answers.

## School 2 — Web, App & UI/UX Design

**What the field does:** designs and builds useful digital products that people can understand and operate.

**Beginner foundations:** browser, URL, request/response, HTML document structure, semantic elements, CSS cascade and box model, responsive layout, JavaScript basics, user goals, visual hierarchy and accessibility.

**Professional progression:** responsive design systems; DOM and browser APIs; forms and validation; frontend framework; state and routing; backend/API and database concepts; authentication/security; performance; testing; deployment. The design route adds research planning, consent, interviews, synthesis, information architecture, wireframes, prototypes, usability testing, design tokens, handoff and iteration.

**Tools to practise:** browser devtools, VS Code, Git, Figma or an accessible alternative, HTML/CSS/JavaScript, a framework when fundamentals are secure, accessibility inspection tools and a deployment service.

**Portfolio sequence:**
- Beginner: accessible responsive multi-page site.
- Intermediate: interactive application with search/filter, forms, loading/empty/error states and API/data integration.
- Advanced: product case study from research to prototype to deployed implementation, including usability findings, accessibility fixes and design rationale.

**Entry roles:** junior frontend developer, web content developer, UI designer, UX research/design assistant. UX roles require research evidence; frontend roles require working code.

**Hiring proof:** semantic HTML; responsive CSS; JavaScript interaction; keyboard navigation; accessible labels and focus; browser debugging; design rationale; usability task plan; clear prototype handoff.

**Interview preparation:** box model, Flexbox/Grid, DOM/events, async requests, semantic HTML, accessibility, responsive breakpoints, usability methods, design systems, trade-offs and a case-study walkthrough.

## School 3 — AI, Data Science & Automation

**What the field does:** converts data into decisions, builds predictive systems and automates workflows with measurable reliability.

**Beginner foundations:** files and tables; data types; arithmetic, percentages and graphs; descriptive statistics; probability intuition; Python basics; SQL basics; privacy and data ethics.

**Professional progression:** data cleaning and validation; exploratory analysis; visualisation and storytelling; sampling and uncertainty; hypothesis testing concepts; feature engineering; train/validation/test separation; baselines; metrics; leakage and overfitting; error analysis; ML model selection; neural-network concepts; LLM/token/context/embeddings; retrieval and tool use; evaluation sets; responsible AI; monitoring and deployment. Explain that generated answers can be wrong and require grounding and testing.

**Tools to practise:** Python, notebooks, SQL, spreadsheets, data visualisation/Power BI, Git, a small ML library and carefully selected AI APIs or local tools. Never expose private data or secrets.

**Portfolio sequence:**
- Beginner: clean a fictional dataset, calculate summary statistics and write an insight note.
- Intermediate: SQL + dashboard analysis with reconciled totals and reproducible steps.
- Advanced: evaluated ML or retrieval-based AI prototype with baseline, test set, error analysis, privacy notes, limitations and human fallback.

**Entry roles:** data analyst trainee, reporting analyst, junior BI analyst, automation assistant. Data scientist and ML engineer roles usually require stronger mathematics, coding and domain depth than an introductory course.

**Hiring proof:** write SQL joins/aggregations; clean missing/duplicate data; explain mean vs median; choose a chart; calculate and interpret metrics; detect leakage; compare with a baseline; explain model limitations.

**Interview preparation:** SQL, statistics, sampling, data quality, visual storytelling, train/test split, precision/recall, overfitting, reproducibility, privacy and a project walkthrough.

## School 4 — Electronics, VLSI & Engineering

**What the field does:** applies mathematics and physical principles to design, build, measure and verify electronic and computing systems.

**Beginner foundations:** SI units and prefixes; dimensional analysis; algebra and equation rearrangement; graphs; trigonometry and vectors; complex numbers and phasors; calculus and differential-equation intuition; signals/frequency response; probability and measurement uncertainty; physics of charge, energy and fields; electrical safety and lab practice.

**Professional progression:** Ohm's law; series/parallel; KCL/KVL; node/mesh analysis; Thevenin/Norton; RC/RL/RLC transients; diodes; BJT/MOSFET device physics; biasing and small-signal models; analog amplifiers/op-amps; Boolean algebra and digital logic; timing/state machines; embedded C; GPIO, timers, interrupts, ADC, PWM, UART/I2C/SPI; Verilog/SystemVerilog; self-checking testbenches and assertions; FPGA constraints, synthesis and timing; CMOS/VLSI power, performance, area and verification. Teach calculations, assumptions, diagrams, waveforms and measurement uncertainty step by step.

**Tools to practise:** calculator and spreadsheet; circuit simulator; datasheets; Arduino or equivalent microcontroller; HDL simulator; FPGA toolchain where hardware is available; Git and technical report templates. Provide simulation-first routes when learners lack hardware.

**Portfolio sequence:**
- Beginner: analysed resistor network with calculations and simulator evidence.
- Intermediate: sensor-based embedded system with safe wiring, firmware and measured results.
- Advanced: HDL/FPGA controller with specification, testbench, assertions where appropriate, waveforms, synthesis/timing report and design review.

**Entry roles:** electronics test trainee, embedded systems trainee, junior hardware validation technician, FPGA/RTL verification trainee. VLSI design/verification roles require deeper digital logic, HDL, timing and tool-specific practice.

**Hiring proof:** solve circuit problems with units; explain device operation; derive logic; read waveforms; write and debug HDL; explain setup/hold and reset; produce a test plan; interpret measured/simulated results; defend design trade-offs.

**Interview preparation:** KCL/KVL, network theorems, transients, diode/BJT/MOSFET, op-amps, Boolean logic, FSMs, setup/hold, Verilog blocking/nonblocking concepts, testbench design, FPGA constraints and project defence.

**Scope boundary:** this school currently centres on electrical/electronics/VLSI. Mechanical, civil, chemical, biomedical and other engineering disciplines need separate dedicated curricula and projects; do not imply this pathway covers them.

## School 5 — Office, Documents & Productivity

**What the field does:** creates accurate business documents, reports, spreadsheets, presentations, records and repeatable office workflows.

**Beginner foundations:** keyboard/file skills; naming and organising files; saving/exporting; document structure; cells, rows, columns and data types; formulas and relative/absolute references; basic email and calendar etiquette.

**Professional progression:** Word styles, sections, tables, references, track changes and accessible PDF; Excel functions, lookups, validation, cleaning, PivotTables and Power Query; charts and dashboard design; PowerPoint narrative and speaker notes; Outlook/Teams collaboration; Access and relational data; Power BI data models, DAX concepts and security; Power Automate triggers, approvals, exceptions and audit trails. Explain product-version and licence differences.

**Tools to practise:** Microsoft Office or compatible free alternatives; Excel/Sheets; Power BI where available; Outlook/Teams or equivalents; Access/database concepts; Power Automate or alternative workflow tools.

**Portfolio sequence:**
- Beginner: polished accessible report and presentation.
- Intermediate: spreadsheet model with validation, formulas and reconciled outputs.
- Advanced: fictional monthly reporting pack with data model, dashboard, executive memo and documented automation/failure handling.

**Entry roles:** office administrator, operations assistant, reporting assistant, MIS executive trainee, junior data/reporting analyst.

**Hiring proof:** format a document; use formulas and lookups; clean and validate data; build a pivot summary; communicate findings in slides; manage email/calendar professionally; explain permissions and workflow exceptions.

**Interview preparation:** spreadsheet references/functions, lookup logic, pivot tables, data cleaning, document styles, presentation structure, collaboration, confidentiality and accuracy checks.

## School 6 — Personal Finance & Economics

**What the field does:** develops financial literacy and analytical understanding of households, institutions, markets and economic decisions.

**Beginner foundations:** arithmetic, percentages, ratios, time periods, cash flow, income/expense categories, interest, inflation and reading tables/charts.

**Professional progression:** Indian banking and payment systems; statements and reconciliation; simple/compound interest; credit and EMI; fraud prevention and grievance channels; insurance; tax concepts with current jurisdiction context; risk/return; diversification; funds, stocks, bonds, gold and property; fees and liquidity; financial statements; macroeconomic indicators; global markets; source checking and research writing.

**Tools to practise:** spreadsheets, calculators, public regulator/official sources, financial statement templates and charting tools. Use fictional case data for exercises; do not ask learners to upload sensitive personal financial data.

**Portfolio sequence:**
- Beginner: fictional monthly budget and cash-flow plan.
- Intermediate: compare fictional loan/insurance scenarios including fees, exclusions and risks.
- Advanced: analyse a fictional company's statements and write a market/sector research memo separating facts, assumptions and uncertainty.

**Entry roles:** finance operations trainee, banking operations associate, accounts/finance assistant, junior research/data support (with additional role-specific requirements). Personal finance literacy alone does not qualify someone as an investment adviser.

**Hiring proof:** reconcile a statement; calculate interest/EMI; interpret basic financial statements; explain risk and diversification; cite current official sources; distinguish return assumptions from guarantees.

**Interview preparation:** banking basics, inflation, interest, credit, insurance, financial statements, ratios, market concepts, compliance awareness, confidentiality and source credibility.

## School 7 — Business, Accounting & Management

**What the field does:** records business activity, measures performance, plans resources and improves customer and operating outcomes.

**Beginner foundations:** arithmetic, percentages, tables, spreadsheets, business vocabulary, revenue vs profit vs cash, customer/problem/value.

**Professional progression:** accounting equation; double-entry; journals/ledgers/trial balance; financial statements; accruals and working capital; budgets and forecasts; contribution margin and break-even; unit economics; market research; marketing/sales funnels; operations and process mapping; inventory/quality; project management; KPIs; governance, ethics and controls.

**Tools to practise:** spreadsheets, accounting practice ledgers, presentation tools, process maps, project trackers and BI dashboards. Use fictional businesses and clearly labelled assumptions.

**Portfolio sequence:**
- Beginner: record transactions and prepare a trial balance.
- Intermediate: produce basic financial statements and a three-scenario budget.
- Advanced: business case with market evidence, unit economics, process map, KPI dashboard, risks and an executive presentation.

**Entry roles:** accounts assistant, business operations trainee, junior business analyst, sales/operations coordinator.

**Hiring proof:** record transactions accurately; reconcile totals; explain profit vs cash; build a forecast; analyse a process; define KPIs; communicate a recommendation with evidence.

**Interview preparation:** accounting equation, debits/credits, statements, working capital, break-even, unit economics, market research, operations metrics and stakeholder communication.

## School 8 — IT, Networking, Cloud & Cybersecurity

**What the field does:** keeps computing services available, connected, secure and recoverable.

**Beginner foundations:** computer hardware/software; operating systems; files, processes and permissions; binary/decimal/hexadecimal; terminal; network devices; IPv4 structure; safe lab rules.

**Professional progression:** Windows/Linux administration; command line and scripting; TCP/IP; subnetting/CIDR; DNS/DHCP/NAT/routing; HTTP/TLS; troubleshooting methodology; virtual machines and containers; cloud fundamentals and shared responsibility; IAM/MFA/least privilege; backups; defensive security; patching; logs and monitoring; incident response; recovery; DevOps and CI/CD.

**Tools to practise:** Linux VM, terminal, packet analysis tools, network simulators, Git, cloud free tiers only with budget alerts, log tools and isolated lab environments. Cybersecurity exercises must be authorised and defensive.

**Portfolio sequence:**
- Beginner: IP/subnet plan and documented troubleshooting of a fictional network.
- Intermediate: configure a small authorised lab with users, permissions, services and backups.
- Advanced: secure deployment architecture with IAM, logging, threat model, incident runbook and recovery test.

**Entry roles:** IT support/helpdesk trainee, desktop support, junior network support, cloud support trainee. Security analyst roles need extra supervised practice and strong foundations.

**Hiring proof:** troubleshoot methodically; subnet correctly; explain DNS/DHCP/HTTP; use Linux commands; manage permissions; identify suspicious logs; explain least privilege, backup and incident escalation.

**Interview preparation:** OS basics, TCP/IP, subnetting, DNS, DHCP, ports, Linux, permissions, IAM, phishing, patching, backups, monitoring and customer communication.

## School 9 — Career & Professional Skills

**What the field does:** helps learners translate actual competence into credible applications and effective workplace behaviour.

**Beginner foundations:** self-assessment; truthful education/work history; file and email basics; clear written communication; reading job descriptions; professional conduct and privacy.

**Professional progression:** role research; skills-gap matrix; evidence-based CV/resume; portfolio and Git hygiene; application tracking; recruiter communication; behavioural interviews using STAR; technical interview practice; presentations and group work; meeting notes; feedback; workplace ethics; job-search scam awareness and negotiation basics.

**Tools to practise:** document editor, spreadsheet tracker, portfolio/GitHub/LinkedIn where appropriate, calendar and video-call tools. No paid service should be mandatory.

**Portfolio sequence:**
- Beginner: one-page truthful CV and skills inventory.
- Intermediate: two project case studies with screenshots, role relevance and personal contribution.
- Advanced: role-specific application pack, mock interview recordings/feedback, technical practical and improvement plan.

**Entry roles:** this school supports every other school; it is not usually a stand-alone job qualification. Professional communication and career operations skills strengthen applications.

**Hiring proof:** explain experience honestly; tailor a CV without keyword stuffing; demonstrate projects; answer behavioural questions with evidence; ask relevant questions; communicate clearly.

**Interview preparation:** tell-me-about-yourself, project deep dive, conflict/learning example, strengths/gaps, role motivation, technical explanation and questions for the employer.

## School 10 — Creative & Digital Media

**What the field does:** communicates ideas through visual design, branding, image, audio, video, motion and content systems.

**Beginner foundations:** file formats, resolution, aspect ratios, composition, hierarchy, typography, colour, audience, message, consent and copyright/licensing.

**Professional progression:** raster vs vector; brand systems; image editing; audio recording/editing; video cuts and pacing; storyboarding; motion/keyframes; subtitles/captions; accessibility; export settings; content strategy; platform specifications; analytics; asset licensing and client handoff.

**Tools to practise:** free-first image/vector/audio/video editors, camera/phone capture, caption tools and asset-management workflow. Teach concepts independently of a single paid product.

**Portfolio sequence:**
- Beginner: edited image set and a simple poster with source/asset credits.
- Intermediate: brand identity kit and short captioned video.
- Advanced: multi-format campaign with motion, audio, content calendar, analytics interpretation, licensing record and case study.

**Entry roles:** junior graphic designer, content assistant, video editor trainee, social media creative assistant. Each role needs a focused portfolio.

**Hiring proof:** show original editable work; explain hierarchy and audience; deliver correct exports; caption media; document licensed assets; respond to a revision brief.

**Interview preparation:** design rationale, typography/colour, file formats, export settings, editing workflow, copyright, accessibility, deadlines and critique response.

## School 11 — Personal Productivity & Knowledge

**What the field does:** improves how people plan, learn, make decisions and manage work. It is a transferable capability, not usually a stand-alone hiring credential.

**Beginner foundations:** goals, tasks, calendar/time awareness, notes, priorities, realistic workload and basic file organisation.

**Professional progression:** task decomposition; estimation; prioritisation; calendar planning; focus; meeting notes; knowledge capture and retrieval; active recall and spaced practice; decision logs; retrospectives; lightweight automation; sustainable routines and privacy.

**Tools to practise:** paper or digital notes, calendar, spreadsheet/task manager and simple automation. The system should remain portable and not depend on one subscription.

**Portfolio sequence:**
- Beginner: weekly plan with realistic time estimates.
- Intermediate: study/project knowledge base with retrieval practice and review.
- Advanced: documented project operating system with milestones, risk log, decisions, retrospective and measurable process improvement.

**Career relevance:** demonstrate reliability through project delivery, clear notes, deadlines, communication and continuous learning. Do not present productivity app familiarity as equivalent to domain skill.

## School 12 — Mathematics, Science & Research

**What the field does:** provides quantitative reasoning, scientific understanding and the ability to investigate questions using reproducible evidence.

**Beginner foundations:** number sense; arithmetic; fractions/decimals/percentages; ratios; units; algebra; graphs; geometry and scientific vocabulary.

**Professional progression:** functions; trigonometry and vectors; limits/calculus; linear algebra foundations; probability/statistics; physics and chemistry principles; measurement and uncertainty; experimental design; scientific method; literature search; source evaluation; data analysis; reproducibility; research ethics; technical writing and citation.

**Tools to practise:** calculator, spreadsheet, graphing tool, Python or equivalent for analysis, lab/simulation tools where appropriate and reference-management/citation workflow.

**Portfolio sequence:**
- Beginner: fully worked problem set with reasoning and units.
- Intermediate: small experiment or simulation with method, data, uncertainty and graphs.
- Advanced: reproducible research-style report with research question, sources, method, analysis, limitations, ethics and citations.

**Entry roles:** research assistant or lab/data support roles may be possible with relevant domain qualifications and supervised experience. Quantitative analyst, scientist and engineering roles require deeper specialist education and role-specific credentials.

**Hiring proof:** solve unfamiliar problems; show derivations; interpret data; design a fair test; explain uncertainty and limitations; write a reproducible report.

**Interview preparation:** mathematics fundamentals, statistics, scientific reasoning, experimental design, data interpretation, technical writing and domain-specific questions.

## Cross-school job-readiness checklist

A learner should not be marked job-ready until they can demonstrate the following for their chosen role:

- [ ] A role-specific skills map based on real entry-level job descriptions.
- [ ] Prerequisites and foundational concepts explained without unexplained jumps.
- [ ] Independent practical tasks completed under realistic constraints.
- [ ] At least three original portfolio projects at increasing difficulty, or the equivalent evidence expected in that profession.
- [ ] Tests, calculations, validation, usability, safety or other quality checks appropriate to the field.
- [ ] Clear README/report/case study describing problem, process, decisions, evidence and limitations.
- [ ] A live project walkthrough and response to an unfamiliar change request.
- [ ] A truthful role-specific CV and application materials.
- [ ] Technical and behavioural mock interview practice with feedback.
- [ ] Awareness of professional ethics, privacy, security, accessibility and when to escalate or seek supervision.
- [ ] A continuing learning plan based on gaps found in practical assessments.

## How SkillSpring should assess each course

Use a transparent rubric rather than a completion badge alone:

| Dimension | What is assessed |
|---|---|
| Understanding | Explains concepts and terminology accurately |
| Execution | Completes the task correctly without copying |
| Reasoning | Shows calculations, design choices or problem-solving steps |
| Verification | Tests normal, boundary and failure cases |
| Professional quality | Follows relevant standards, safety, privacy and accessibility |
| Communication | Documents and explains work clearly |
| Independence | Handles an unfamiliar variation and knows when to ask for help |

A course can be labelled **Foundation**, **Practitioner** or **Role-ready pathway** only when its content and assessments genuinely support that level. Do not label a learner or course “professional” merely because a topic list is long.
