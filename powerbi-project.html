02 · THE BUSINESS BRIEF

What does the manager need to know?

You are a junior analyst supporting a small retailer. The manager wants to understand performance during 2025.

  1. What were total sales, total cost and gross profit?
  2. How did sales change month by month?
  3. Which products and categories contributed most?
  4. Which region generated the highest sales and profit?
  5. What was the average order value?
  6. What data-quality limitations should be disclosed?
03 · IMPORT AND CLEAN

Prepare the data in Power Query

  1. Open Power BI Desktop and choose Get data → Text/CSV.
  2. Import all three files and rename the queries to Sales, Products and Regions.
  3. Set OrderDate to Date; Quantity to Whole number; UnitPrice, UnitCost, SalesAmount, CostAmount and DiscountPct to Decimal number; IDs and names to Text.
  4. Inspect nulls, duplicate order IDs, blank product/region IDs and unusual values.
  5. Use repeatable transformations only when justified. Do not silently delete questionable records.
  6. Select Close & Apply.
Checkpoint: Sales should contain 36 rows. Every Sales ProductID and RegionID should match a row in its dimension table.
04 · BUILD THE DATA MODEL

Connect facts to dimensions

Create one-to-many relationships with single-direction filtering from the dimension tables into Sales.

Products[ProductID]1 → *Sales[ProductID]
Regions[RegionID]1 → *Sales[RegionID]

Create a date table using Modeling → New table:

Date =
CALENDAR(
    MIN(Sales[OrderDate]),
    MAX(Sales[OrderDate])
)

Add these calculated columns:

Year = YEAR('Date'[Date])
Month Number = MONTH('Date'[Date])
Month = FORMAT('Date'[Date], "MMM")

Sort Date[Month] by Date[Month Number], then relate Date[Date] 1 → many to Sales[OrderDate]. Mark the table as a date table if that option is available in your Power BI version.

05 · WRITE DAX MEASURES

Turn transactions into useful metrics

Create these measures in the Sales table or a dedicated Measures table.

Total Sales = SUM(Sales[SalesAmount])

Total Cost = SUM(Sales[CostAmount])

Gross Profit = [Total Sales] - [Total Cost]

Profit Margin = DIVIDE([Gross Profit], [Total Sales])

Total Orders = DISTINCTCOUNT(Sales[OrderID])

Units Sold = SUM(Sales[Quantity])

Average Order Value = DIVIDE([Total Sales], [Total Orders])

Format the sales, cost, profit and average order value measures as currency. Format Profit Margin as a percentage.

Understand this: A measure recalculates in the current filter context. When a user selects a region or month, the same measure returns a different result for that selection. DIVIDE also lets you handle a zero denominator safely.
06 · DESIGN YOUR REPORT

Build two useful report pages

Overview page

  • KPI cards: Total Sales, Gross Profit, Profit Margin, Total Orders and Average Order Value.
  • Line chart: Total Sales by Date[Month].
  • Bar chart: Total Sales by Regions[RegionName].
  • Bar chart: Gross Profit by Products[Category].
  • Table: ProductName, Units Sold, Total Sales and Gross Profit.
  • Slicers: Year, RegionName and Category.

Product detail page

  • Compare products by sales and gross profit.
  • Show category contribution.
  • Allow users to filter by region and date.
  • Use clear titles, labels and number formats.
  • Keep contrast readable and avoid decorative visuals that do not answer a question.
07 · VALIDATE BEFORE YOU PRESENT

Check that your report is trustworthy

  • Sales has 36 rows and 36 unique order IDs.
  • Every transaction has a valid product and region.
  • Total Sales and Total Cost match independent sums from the CSV.
  • Region and month selections update the KPI cards.
  • Month is sorted chronologically, not alphabetically.
  • Profit Margin is total gross profit divided by total sales, not an unweighted average of row percentages.
  • Assumptions and limitations are documented.

If totals differ, inspect data types, relationship direction, duplicate rows and DAX expressions before changing the source data.

08 · PORTFOLIO EVIDENCE

Package your work professionally

  1. PBIX project file.
  2. PDF export or clear report screenshots.
  3. Data model diagram.
  4. One-page data dictionary.
  5. DAX measures with plain-language explanations.
  6. Validation checklist.
  7. A short business recommendation supported by the report.
  8. A 3–5 minute walkthrough explaining the question, data, model, measures, insight and limitations.

Prepare to answer these questions

  • Why did you separate Sales, Products and Regions?
  • What is the grain of the Sales table?
  • What is the difference between a measure and a calculated column?
  • What is filter context?
  • How did you validate the totals?
  • How would you restrict regional managers to their own region?
